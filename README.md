# alirezaserver · 0.8.0-rc.16

نوا با Alirezabot مبتنی بر **میرزای کامل**؛ فروش نمایندگی مالک و ربات مستقل هر نماینده، در همان رابط وب میرزا.

این نسخه روی rc.15 ساخته شده است. مسیرهای تولید کانفیگ، TLS، هسته‌های پروتکل و آپدیتر نوا تغییر نکرده‌اند. این بسته نامزد انتشار است؛ ادعای بدون باگ یا تست کامل روی VPS ندارد. [آزمون‌ها و محدودیت‌ها](docs/RC16-VALIDATION.md) · [فایل‌های تغییرکرده و هش موارد حفظ‌شده](docs/RC16-BASELINE.json)

## اصلاح فرم فروش و دسترسی‌ها

فرم فروش نمایندگی در **همان پنل وب میرزا، صفحهٔ `panel/reseller.php`** مرتب شده است: متن‌ها اندازه و فاصلهٔ خوانا دارند؛ برچسب‌ها و شناسه‌های فنی می‌شکنند؛ checkboxها عرض ثابت و کارت مستقل دارند. مجوزها ترجمهٔ فارسی، شناسهٔ فنی، جست‌وجو، انتخاب موارد نمایان و شمارندهٔ انتخاب دارند. رنگ‌ها از متغیرهای واقعی تم میرزا گرفته می‌شوند و دیگر صفحات بازطراحی نشده‌اند.

## تخصیص گروهی اینباند به حساب‌های موجود

از بالای همین صفحه، «تخصیص گروهی اینباند» را بزنید:

۱. نوع حساب را انتخاب کنید: **نمایندگان نوا با نقش reseller** یا **کاربران VPN**. نقش‌های مدیریتی سراسری در فهرست نمایندگان نیستند. اعطای دسترسی به نماینده و مشتریان فعلی او دو عملیات جدا هستند. اگر ویرایش نماینده در نوا خطر محدودکردن دسترسی مستقل مشتریانش را داشته باشد، آن حساب متوقف و نیازمند بررسی اعلام می‌شود؛ برای افزودن مستقیم به مشتریان، نوع «کاربران VPN» را انتخاب کنید.

۲. نام/شناسه را جست‌وجو و حساب‌ها را انتخاب کنید. انتخاب این صفحه یا همهٔ نتایج جست‌وجو در دسترس است؛ انتخاب‌ها با ورق‌زدن صفحات حفظ می‌شوند.

۳. اینباندهای فعال جدید را انتخاب و **پیش‌نمایش** بگیرید. هنوز هیچ تغییری انجام نشده است. دسترسی‌های قبلی کنار دسترسی نتیجه نشان داده می‌شوند. پیش‌نمایش تا ۱۵ دقیقه معتبر است؛ اگر دسترسی هم‌زمان عوض شود، آن حساب بدون بازنویسی نیازمند بررسی می‌ماند.

۴. پس از بررسی، **تأیید و اعمال** را بزنید. اجرا در پس‌زمینه و در دسته‌های کوچک انجام می‌شود؛ بستن صفحه عملیات را حذف نمی‌کند. شمارنده و نوار پیشرفت از وضعیت ذخیره‌شدهٔ هر حساب می‌آیند. موارد خطا قابل فیلتر و تلاش مجددند. پس از قطع پردازش، بازیابی lease ممکن است تا سه دقیقه زمان ببرد.

۵. از «عملیات‌های اخیر» نتیجه را دوباره باز کنید. توقف بعد از درخواست جاری انجام می‌شود، نه اینکه درخواستِ ارسال‌شده نادیده گرفته شود. بازگشت موارد موفق ابتدا پیش‌نمایش می‌دهد و تأیید جدا می‌خواهد؛ اگر دسترسی بعداً تغییر کرده باشد، بازگشت خودکار برای جلوگیری از تداخل رد می‌شود. موارد خطای نامطمئن را ابتدا بررسی/ادامه دهید. بازگشت خودکار دسترسی نماینده‌ای که مشتری زیرمجموعه دارد، برای جلوگیری از قطع دسترسی آن‌ها انجام نمی‌شود؛ آن مورد نیاز به بررسی دستی در نوا دارد.

**این عملیات افزایشی است:** اینباند قبلی حذف نمی‌شود؛ حجم، UUID، رمز، تاریخ انقضا و نقش عمداً تغییر نمی‌کنند. حسابِ دارای دسترسی به همهٔ اینباندها محدود نمی‌شود. تنظیمات خود اینباند، پورت، TLS یا پروتکل بازنویسی نمی‌شود. برای دیدن اینباند جدید، کاربران باید اشتراک خود را تازه کنند؛ شناسه و رمز قبلی عوض نمی‌شود. اعمال دسترسی با API خود نوا انجام می‌شود و رفتار بارگذاری مجدد هسته تابع نواست؛ وعدهٔ بدون وقفه برای همهٔ شرایط داده نمی‌شود.

حساب‌های انتخابی، پیش‌نمایش و پیشرفت در `shop.db` به‌صورت رمز‌شده ذخیره و با پشتیبان موجود جمع‌آوری می‌شوند. عملیات پرداخت/پلن‌ها و دادهٔ قبلی دست‌نخورده است. برای جمعیت بسیار بزرگ، امکان انتخاب مرحله‌ای و چند عملیات وجود دارد؛ سقف ایمنی هر عملیات ۱۰ هزار حساب است و محدودیت تعداد کل کاربران پنل نیست.

بررسی مستقیم PHP/MariaDB، تست DOM در ورودی عرض‌های موبایل/دسکتاپ و آزمون واقعی API نوا انجام شده است. Chromium دریافت شد ولی محیط هنگام شروع مرورگر SIGTRAP داد؛ **تست تصویری مرورگر موفق اعلام نمی‌شود**. گزارش کامل کنار سورس است.

## نصب و ارتقا

قبل از ارتقا از `sudo alireza` پشتیبان بگیرید و یک نسخه خارج از سرور نگهداری کنید. پس از آپلود فایل‌های جدید روی GitHub:

```bash
curl -fL --connect-timeout 15 --max-time 180 https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezaserver/main/install.sh -o install.sh && sudo bash install.sh
```

نصاب آنلاین است؛ فایل‌های افزونه و سورس میرزا را در خود دارد و وابستگی‌های رسمی را دانلود می‌کند. build رابط کاربری روی VPS انجام نمی‌شود. پایهٔ ثابت نصب تازه نوا 1.92.3 است و بررسی آخرین نسخهٔ رسمی سازگار در پایان نصب انجام می‌شود. نسخهٔ ناسازگار بدون بررسی جایگزین نمی‌شود. تایمر شش‌ساعته و دکمهٔ آپدیت همان مسیر محافظت‌شده را دارند؛ سازگاری با تمام نسخه‌های آینده تضمین نیست.

نصاب جدید را ابتدا کامل اجرا کنید؛ `--update` روی نسخهٔ قبلی، کد rc.15 را نصب نمی‌کند. اجرای دوباره برای تعمیر/ادامه پشتیبانی می‌شود؛ حساب‌ها، تنظیمات، گواهی‌ها و دیتابیس‌ها نباید با پیش‌فرض جایگزین شوند.

```bash
sudo alireza
sudo bash install.sh --check
sudo bash install.sh --update
sudo bash install.sh --update-status
sudo bash install.sh --diagnose
```

## تغییر اصلی این نسخه

- فروشگاه مستقل rc.14 از منوی پنل اصلی حذف شده است. **فروش پنل نمایندگی مالک داخل پنل وب میرزا، صفحهٔ «فروش پنل نمایندگی»** انجام می‌شود.
- نماینده یا ادمین دارای مجوز ساخت کاربر، از گزینهٔ Alirezabot در پنل خودش، **نسخهٔ کامل میرزا** را با توکن اختصاصی راه‌اندازی می‌کند؛ ربات سبک جایگزین میرزا نیست.
- هر نمونه دیتابیس، کاربر سیستم، تنظیمات، رمز وب، نشست‌ها و مسیر مستقل دارد. تم/رنگ ذخیره‌شدهٔ آن نیز به نمونهٔ دیگری نمی‌رود.
- نماینده نمی‌تواند پنل نمایندگی بفروشد؛ این محدودیت در API سرور اعمال می‌شود و تنها به مخفی‌کردن منو وابسته نیست.
- بخش میزبان‌ها از رابط و API مدیریت پنل حذف شده است. پروفایل‌های میزبان موجود در اینباندها و تنظیمات فعال اتصال حذف یا بازنویسی نمی‌شوند.

## راه‌اندازی میرزا برای نماینده یا ادمین

۱. با حساب خودش وارد پنل نوا شود؛ دسترسی‌های لازم ساخت/دیدن کاربران و اینباندها را مالک در پلن مشخص می‌کند.

۲. بخش **Alirezabot** را باز کند، توکن مستقل BotFather و شناسهٔ عددی مدیر تلگرام خودش را وارد و نصب را تأیید کند. توکن اصلی یا توکن مصرف‌شدهٔ نمونهٔ دیگر پذیرفته نمی‌شود.

۳. وضعیت واقعی نصب در همان بخش دریافت می‌شود. بستن صفحه نصب را متوقف نمی‌کند؛ اگر خود پردازش پنل هنگام نصب restart شود، وضعیت قطع‌شده مشخص و اجرای دوباره برای تعمیر لازم است.

۴. پس از نصب، «بازکردن پنل کامل ربات» را بزند و اطلاعات ورود یک‌بارمصرف را ذخیره کند. در صورت فراموشی، همان بخش امکان بازنشانی رمز وب را دارد. توقف، شروع، restart و تعمیر همان نمونه نیز از همان‌جا انجام می‌شود.

این همان رابط وب و امکانات فروش کاربر میرزا است. اتصال محلی به هویت واقعی همان ادمین/نماینده تنظیم می‌شود؛ نمونه به کاربران، پلن‌ها، کیف پول و نشست وب نمونه‌های دیگر دسترسی ندارد. روی حساب حجمی، ساخت کاربر نامحدود، تخصیص بیشتر از سهمیهٔ باقی‌مانده یا بیشتر از ظرفیت کاربران از مسیر ربات رد می‌شود. فروش با خروجی‌های کشور نیز تابع مجوز حساب است.

**هر نمونهٔ کامل میرزا منابع خودش را مصرف می‌کند.** ایجاد یک نمونهٔ جدا برای هر حساب، به معنی امکان اجرای تعداد نامحدود ربات روی رم ۱ GB نیست. نصب اختیاری است؛ تا زمانی که کاربر نصب را انتخاب نکرده، برایش PHP/poller جدا اجرا نمی‌شود.

## فروش نمایندگی مالک

در پنل وب میرزا با حساب مالک، «فروش پنل نمایندگی» را باز کنید. نام پلن، نقش، اینباندها، دسترسی‌ها، قیمت ثابت یا قیمت هر GB، حداقل/حداکثر حجم و ظرفیت کاربران را تعیین کنید.

فقط نقش `reseller` در نوا سهمیهٔ حجمی نماینده دارد. `manager` و `admin1` دسترسی مدیریتی بدون این سهمیه‌اند؛ فرم، تفاوت را مشخص می‌کند. مدت پلن، مدت پیش‌فرض مشتریان نماینده است و انقضای ساختگی حساب ادمین نیست. فروش خودکار `admin1` اختیار گسترده می‌دهد و تأیید رمز مالک می‌خواهد؛ تأیید رمز‌شده ذخیره می‌شود و با تغییر رمز باید دوباره انجام شود.

مشتری در همان ربات اصلی:

- **🛍 خرید پنل نمایندگی**: انتخاب پلن، گزینهٔ **✍️ حجم دلخواه** و کنترل حداقل/حداکثر واقعی، سپس تأیید قیمت محاسبه‌شدهٔ سرور.
- پرداخت از **کیف پول واقعی همان میرزا**؛ تکرار یک سفارش یا قطع پاسخ، برداشت و ساخت حساب را دوباره انجام نمی‌دهد.
- تحویل لینک، نام حساب و رمز و دکمهٔ **🧭 مدیریت پنل من**.

دکمه‌ها و پیام‌های این مسیر آیکون‌های ایموجی دارند. مسیرهای اصلی میرزا و پلن‌های قبلی حذف نشده‌اند.

## مدیریت پنل من در تلگرام

از **🧭 مدیریت پنل من** یا `/mypanels`، پنل‌های خریداری‌شدهٔ همان شناسهٔ تلگرام دیده می‌شوند:

- 📊 سهمیه و حجم باقی‌مانده از دادهٔ واقعی نوا، همراه ظرفیت کاربران باقی‌مانده.
- 🌐 لینک ورود و 🔑 نمایش رمز تحویلی در پیام خصوصی با پوشش spoiler.
- 🔐 تغییر رمز با تأیید، تولید رمز امن و همگام‌کردن اطلاعات تحویل؛ رمز جدید با ورود واقعی نوا آزمایش شده است.
- 🔄 تازه‌سازی و مدیریت چند پنل خریداری‌شده با صفحه‌بندی.

رمزهای نوا قابل استخراج از هش نیستند. اگر رمز را خارج از ربات عوض کرده باشید، رمز ذخیره‌شدهٔ قبلی ممکن است قدیمی باشد؛ دکمهٔ تغییر رمز، رمز تازهٔ معتبر می‌سازد. تغییر مجدد رمز در کمتر از یک دقیقه برای جلوگیری از فشار و کلیک تکراری محدود شده است. رمز را در گروه یا برای دیگران ارسال نکنید. حساب غیرفعال/حذف‌شده یا شناسهٔ تلگرام دیگری اجازهٔ دریافت یا تغییر رمز ندارد.

## اطلاعات قبلی و پشتیبان

دیتابیس و اطلاعات فروشگاه مستقل rc.14 برای بازگشت و بررسی نگهداری می‌شوند؛ مسیر آن از پنل حذف و polling فروشگاه قدیمی متوقف شده است. **موجودی فروشگاه مستقل قدیمی خودکار به کیف پول میرزا منتقل نمی‌شود**؛ اگر آن را با مشتری واقعی استفاده کرده‌اید، قبل از جایگزینی گردش مالی را با پشتیبان تطبیق دهید تا پول دوباره شارژ یا حذف نشود. کیف پول ربات اصلی میرزا در همان دیتابیس قبلی حفظ می‌شود.

پشتیبان افزونه اکنون dump دیتابیس و فایل‌های تمام نمونه‌های مدیریت‌شدهٔ میرزا را نیز جمع می‌کند. آرشیو حاوی کلیدها و رمزهای محرمانه است و نباید عمومی شود. برای بازگردانی، علاوه بر فایل‌ها و مالکیت‌ها، dumpهای `database/azb*.sql` و حساب‌های دیتابیس مربوط نیز باید بررسی شوند؛ بازیابی کامل چندنمونه‌ای روی VPS واقعی در این محیط آزمایش نشده است.

ارتقای نصاب، فایل‌های مدیریت‌شدهٔ نمونه‌های موجود را با پشتیبان قبلی به‌روزرسانی می‌کند و اطلاعات اتصال/دیتابیس آن‌ها را از نو نمی‌سازد. به‌روزرسانی نوا مسیر داده و نصب میرزا را جایگزین نمی‌کند. فایل‌های اجرایی نمونه‌های نمایندگان برای حفظ مرز امنیتی root-owned و مسیرهای runtime مشخص قابل نوشتن هستند.

## پورت‌ها، TLS و منابع

| بخش | دسترسی |
|---|---|
| پنل و پروکسی عمومی | TCP 443؛ پورت اضافی مطابق نصب |
| HTTP و اعتبارسنجی HTTP-01 | TCP 80؛ باید از اینترنت به سرور برسد |
| API داخلی نوا | `127.0.0.1:8088` |
| Xray API | `127.0.0.1:10085` |
| AdGuard DNS | TCP/UDP 53 مطابق تنظیم موجود؛ خودش تغییر نکرده است |
| پنل وب ربات‌ها | همان HTTPS پنل، مسیر و سوکت محلی جدا؛ بدون پورت عمومی تازه |
| پروتکل‌ها | پورت انتخابی خودشان در پنل |
| نصب alirezadns مقصد | SSH سرور مقصد، تنها با تأیید نصب |

تنظیمات اتصال، گواهی، DNS، هسته‌ها و آپدیتر نوا دست‌نخورده‌اند؛ پینگ و دسترسی از همهٔ اپراتورها قابل تضمین نیست. باز بودن فایروال ارائه‌دهندهٔ VPS و تناسب دامنهٔ پروکسی‌شده با پروتکل همچنان لازم است.

PHP از حالت ondemand استفاده می‌کند؛ کارهای طولانی نصب در پس‌زمینه و به‌صورت مرحله‌ای اجرا می‌شوند، عملیات بسته‌های نصب هم‌زمان سری می‌شوند، لاگ‌ها چرخش دارند و UI روی سرور build نمی‌شود. نتیجهٔ مصرف کنترلر در گزارش است؛ این عدد مصرف کل MariaDB، PHP، ربات‌ها و ترافیک VPN نیست. نصب/بار کامل روی ۱ GB در این محیط تأیید نشده است.

## آزمون و عیب‌یابی

[گزارش rc.15](docs/RC16-VALIDATION.md) جزئیات API واقعی نوا، تغییر رمز و ورود، جداسازی نمایندگان، کیف پول MySQL، قالب میرزا و انتقال‌های واقعی محلی Xray را مشخص می‌کند. نصب چند نمونه روی VPS واقعی، Telegram واقعی، تست بصری مرورگر و بار بلندمدت همچنان نیاز به آزمایش staging دارند.

```bash
sudo bash install.sh --diagnose
sudo journalctl -u nova-agent.service -n 80 --no-pager
sudo journalctl -u alireza-update.service -n 80 --no-pager
```
