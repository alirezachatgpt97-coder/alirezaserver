# alirezaserver 0.8.0-rc.2

بستهٔ کد و نصب قابل بررسی برای ادغام امکانات NOVA X PANEL در alirezaserver. **این نسخه نامزد آزمایش است، نه تأیید نهایی Production یا ادعای «بدون باگ».** رابط اصلی نوا و AdGuard در این تغییرات بازطراحی نشده‌اند. وضعیت دقیق انتقال و موارد باقی‌مانده در [گزارش انتقال](docs/NOVA-X-REVIEW.md) آمده است.

## امکانات این بسته

| بخش | پیاده‌سازی |
|---|---|
| ساخت دستی اینباند | شش تب مشخصات، پروتکل، انتقال، امنیت، Sniffing و پیشرفته؛ TLS/Reality/SNI/ALPN/کلیدها، socket/MSS/keepalive و تنظیمات WS/gRPC؛ استفاده از کاربران و API اصلی نوا؛ KCP سازگار با FinalMask هستهٔ جدید و fallbackهای قابل ویرایش |
| سایر پروتکل‌های موجود | فرم‌ها و موتورهای native نوا و OpenVPN حفظ شده‌اند؛ فهرست انتخاب از امکانات واقعی نصب می‌آید |
| میزبان‌ها | پروفایل‌های native با ذخیرهٔ تراکنشی؛ افزودن گروهی، جست‌وجو، تکثیر، ترتیب، فعال/پنهان، TLS/SNI/ALPN، Mux/Sockopt/FinalMask، محدودسازی خروجی و نود |
| Hashem | داخل همان صفحهٔ Tunnel؛ GRE/FRP/Backhaul، Carrier، watchdog، پورت‌ها، فرمان نصب مقصد، SSH با اثرانگشت، job پایدار، لاگ، benchmark واقعی TCP، تنظیم FRP/pool، ساخت اینباند متناظر و snapshot/restore |
| alirezabot | ربات کامل PHP مرجع با رابط وب مستقل و رنگ/فونت اصلی؛ مدیریت نصب/سرویس در پنل نوا؛ adapter حساب‌های native با مالکیت جداگانه |
| AI | Gemini رسمی، مدل‌های سازگار دریافت‌شده از API، ذخیرهٔ اتمیک کلید/مدل، streaming، توقف، تلاش مجدد و تاریخچهٔ جداگانه |
| alirezadns | نصب مقصد SSH با preflight/اثر انگشت و وضعیت job؛ هماهنگی رنگ و کنترل‌ها با نوا |

این ادغام روی معماری متفاوت Nova پیاده شده و کپی یک‌به‌یک همهٔ موتورهای مرجع نیست. L2TP اضافه نشده است. گزینهٔ بی‌عمل برای موتور فاقد backend ساخته نشده است. تنظیمات میزبان وابسته به فرمت خروجی‌اند؛ انتخاب ناسازگار صریحاً رد می‌شود، نه اینکه امنیت بی‌صدا حذف شود. محدودیت منابع بازسازی miniapp مرجع نیز در گزارش انتقال آمده است.

## دقیقاً چه چیزهایی در ریشهٔ GitHub قرار بگیرد؟

ZIP را باز کنید و **همهٔ محتویات آن را مستقیم در ریشهٔ مخزن alirezaserver** کپی کنید:

- `install.sh`، `setup.sh`، `README.md`، `CHANGELOG.md`، `SOURCES.md`، `LICENSE`، `SHA256SUMS` و `.gitignore`
- پوشه‌های `addon/`، `core/`، `docs/`، `tests/` و `tools/` با تمام محتویات

خود ZIP یا یک پوشهٔ اضافی دور فایل‌ها را جای این ساختار نگذارید. `setup.sh` و `install.sh` باید از یک بسته باشند؛ launcher هش نصاب را بررسی می‌کند. در این کار چیزی روی GitHub منتشر نشده است.

## پیش‌نیاز و نصب

Ubuntu 24.04 یا Debian 12/13، systemd، amd64/arm64 و root؛ دسترسی اینترنت برای بسته‌های رسمی و TUN برای موتورهای نیازمند آن. ربات PHP **8.2 یا جدیدتر** و MariaDB می‌خواهد. ظرفیت کل مجموعه روی یک گیگ RAM تأیید نشده است.

بعد از بارگذاری فایل‌ها در مخزن خودتان:

```bash
curl -fL --proto '=https' --tlsv1.2 https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezaserver/main/setup.sh -o /root/alirezaserver-setup.sh && sudo bash /root/alirezaserver-setup.sh
```

یا از ZIP استخراج‌شده:

```bash
sudo bash install.sh
```

این نصاب آنلاین است؛ افزونه‌ها و carrier آماده در آن جاسازی شده‌اند، اما نوا، Xray، FRP/Backhaul و بسته‌های سیستم از منابع قفل‌شده/رسمی دریافت می‌شوند. روی VPS ساخت Go/npm انجام نمی‌شود. نصب اختیاری ربات و Hashem فقط با اقدام مالک پنل آغاز می‌شود. منتظر پیام **ALIREZASERVER READY** بمانید.

## ارتقای نسخهٔ موجود

ابتدا پشتیبان مستقل نوا/VPS را بگیرید. سپس با فایل همین بسته:

```bash
sudo bash install.sh --backup
sudo bash install.sh
sudo bash install.sh --check
```

اگر نصب قبلی افزونه وجود ندارد، `--backup` در دسترس نیست؛ بکاپ پنل فعلی را مستقل تهیه کنید. نصب مجدد، پایگاه دادهٔ native و حساب‌های OpenVPN را از نو ایجاد نمی‌کند. بکاپ افزونه با وجود ربات شامل dump تراکنشی دیتابیس `alirezabot`، تنظیمات، گواهی‌ها و فایل‌های اختصاصی ربات/Hashem نیز می‌شود. این آرشیو حاوی اسرار است؛ آن را عمومی نکنید.

```bash
sudo bash install.sh --rollback
```

`--rollback` افزونه‌های قبلی را غیرفعال می‌کند و **downgrade یا restore کامل پایگاه داده نیست**. برای بازیابی کامل snapshot نوا و آرشیو افزونه را به نسخهٔ متناظر برگردانید؛ [راهنمای ارتقا و بازیابی](docs/UPGRADE.md). Snapshot داخل Hashem فقط تنظیمات و سرویس‌ها و قواعد اختصاصی خودش را برمی‌گرداند؛ تونل‌های native را دستکاری نمی‌کند. سرویس‌های اختیاری Hashem/ربات را پیش از غیرفعال‌سازی کامل افزونه از صفحهٔ خودشان متوقف کنید.

## استفاده از Hashem

داخل Tunnel، بخش NOVA Tunnel را باز کنید. نصب هسته‌ها را انجام دهید؛ سپس در هر سمت نقش Iran/foreign و IPv4 عمومی همان سرور و طرف مقابل، موتور، انتقال، پورت‌های مقصد و توکن یکسان تعیین کنید. سه روش وجود دارد: تنظیم همین سرور، فرمان مقصد، یا SSH مقصد. فرمان مقصد بعد از انتشار فایل‌ها در مخزن خودتان کار می‌کند و checksum دارد؛ **فرمان شامل توکن محرمانه است**.

SSH ابتدا اثرانگشت می‌گیرد؛ آن را از مسیر مستقل با سرور مقصد تطبیق دهید و سپس تأیید کنید. رمز/کلید SSH در job ذخیره نمی‌شود. مالک باید GRE/UDP/TCP لازم را در فایروال خارجی سرویس‌دهنده مجاز کند. WSS دارای گواهی خودامضا نیازمند انتخاب صریح گزینهٔ اعتماد ناامن است؛ این حالت معادل تأیید هویت یک گواهی معتبر نیست.

Carrier فقط برای موتور دارای GRE است. پورت‌های Backhaul در سمت Iran مدیریت می‌شوند. «active» بودن systemd به‌تنهایی اثبات سلامت انتهابه‌انتها نیست. benchmark پنل TCP connect است، نه ICMP ping یا اندازه‌گیری packet loss. نصب WAN/GRE واقعی در این محیط آزمایش نشده است.

پورت‌ها و Carrier و نقطهٔ بازگشت فرم داخلی دارند. برای FRP می‌توان encryption/compression/multiplexing و pool را تغییر داد؛ تنظیم‌های متناظر باید دو سمت هماهنگ باشند. تغییر پورت روی Backhaul سمت Foreign فقط اطلاعات محلی را ثبت می‌کند و باید با دستور تولیدشده روی Iran نیز اعمال شود. دستور فقط adapter نصب‌شدهٔ همین ادغام را اجرا می‌کند. ساخت اینباند متناظر، VLESS/WS بدون TLS و بدون تخصیص خودکار کاربر است؛ کاربران را بعداً صریحاً در اینباند انتخاب کنید.

## میزبان‌های پیشرفته

تنظیمات میزبان فقط خروجی اشتراک را تغییر می‌دهند؛ کاربران، شنونده‌ها و سرویس‌ها restart نمی‌شوند. ذخیرهٔ گروهی یک تراکنش SQLite با بررسی نسخهٔ قبلی است. Mux/Sockopt/FinalMask برای Xray هستند. همهٔ گزینه‌های Xray در Sing-box معادل امن ندارند؛ آن فرمت را از میزبان ناسازگار مستثنا کنید. KCP در Sing-box پشتیبانی نمی‌شود. Reality نیازمند اینباند Reality واقعی است. SNI پایه با گزینهٔ حفظ SNI بازنویسی نمی‌شود. قابلیت X25519 اختصاصی Mihomo که در مرجع فقط ذخیره می‌شود، به‌عنوان قابلیت فعال ادعا نمی‌شود.

## alirezabot

مالک از ورودی alirezabot، توکن BotFather، Chat ID مدیر و URL عمومی کامل ربات را وارد می‌کند. PHP-FPM اختصاصی به شکل on-demand، poller غیر root، cron timer و دیتابیس مستقل نصب می‌شوند. وب ربات روی مسیر همان پنل و از طریق socket خصوصی PHP کار می‌کند؛ پورت FPM عمومی باز نمی‌شود. ورود مستقل وب با `admin` و رمز تولیدشدهٔ یک‌بارنمایش است؛ برای بازنشانی گزینهٔ مربوط را بزنید.

در رابط مستقل اصلی، محصولات، قیمت، کاربر، فاکتور، درگاه و سایر تنظیمات خود ربات مدیریت می‌شوند. CSS و فونت‌های مرجع حفظ شده‌اند؛ branding به alirezabot و لینک Source اضافه شده است. adapter محلی نوع `x-ui_single` فقط حساب‌هایی را که خودش ایجاد کرده مدیریت می‌کند؛ حساب‌های قدیمی مالک را تصاحب نمی‌کند. قابلیت on-hold با زمان منفی در native نوا پشتیبانی ندارد و صریحاً رد می‌شود. آمار جهت ارسال/دریافت مستقل موجود نیست؛ adapter مجموع مصرف واقعی را با پرچم نبود تفکیک جهت گزارش می‌کند.

poller جدید پیام را پیش از اجرا در inbox خصوصی ثبت می‌کند. خطاها برای بازبینی باقی می‌مانند؛ retry فقط با تأیید مالک و بررسی نتیجهٔ مالی قبلی است. اجرای دقیقاً یک‌بارِ تراکنش خارجی بعد از crash تضمین نمی‌شود. اتصال تلگرام فقط با پاسخ واقعی polling موفق نشان داده می‌شود و active بودن سرویس کافی نیست. اعتبارسنجی TLS درخواست‌های تلگرام فعال است.

تلگرام زنده، خرید واقعی و درگاه پرداخت در این محیط آزمایش نشده‌اند. نام دامنه/گواهی معتبر و دسترسی سرور به Telegram لازم است. حذف سرویس ربات، دیتابیس و تنظیمات را حذف نمی‌کند. منابع و مجوز AGPL به همراه بسته و از لینک Source رابط ربات قابل دریافت‌اند.

## Gemini و alirezadns

مالک کلید Gemini را در تنظیمات AI وارد می‌کند، «دریافت مدل‌های سازگار» را می‌زند و مدل را انتخاب می‌کند. کلید در سمت سرور رمزگذاری و در header درخواست رسمی استفاده می‌شود؛ مدل محلی نصب نمی‌شود. هیچ اطلاعات محرمانه‌ای خودکار برای مدل ارسال نمی‌شود. نبود کلید، سهمیه، timeout و پاسخ خراب از بقیهٔ پنل جدا مدیریت می‌شوند.

alirezadns برای **سرور مقصد جداگانه** است. اطلاعات SSH، اثرانگشت و پیش‌نیازها را بررسی و سپس نصب را صریحاً آغاز کنید. این تغییرات رابط خود AdGuard یا سرویس DNS فعلی را بازنویسی نمی‌کنند.

## مصرف منابع و کیفیت

در آزمون محدود HTTP/controller، heap حدود ۳۰ MiB و peak RSS حدود ۱۰۲ MiB پس از راه‌اندازی و ۱۵۸ MiB بعد از ۵۰ درخواست ترتیبی اندازه‌گیری شد. این اعداد **مصرف کل سرویس‌ها، بار VPN یا تضمین یک گیگ نیستند**؛ [خروجی اندازه‌گیری](docs/resources-rc2.json).

نمای OpenVPN به‌صورت lazy، PHP به‌صورت on-demand، statusهای همزمان به‌صورت coalesced و polling Hashem فقط هنگام job فعال انجام می‌شوند. carrierها پیش‌ساخته‌اند. قواعد MSS فقط به رابط اختصاصی تونل محدودند و فقط قواعد tagged خود ادغام در rollback تغییر می‌کنند؛ UFW و sysctl سراسری بازنویسی نمی‌شوند. جزئیات ظاهری برای بهینه‌سازی حذف نشده‌اند.

آزمون‌ها و محدودیت‌ها: [VALIDATION](docs/VALIDATION.md). مرورگر این محیط اجرا نشد؛ بررسی تصویری واقعی موبایل/دسکتاپ، نصب systemd روی VPS، WAN/GRE، فشار طولانی و آزمایش کل مجموعه روی ۱GiB انجام نشده‌اند.

## توسعه

```bash
python3 tools/build-hashem-installer.py
python3 tools/build.py
bash install.sh --self-test
python3 tools/package.py ../alirezaserver-0.8.0-rc.2-review.zip
```

سورس carrier و وابستگی WebSocket در `core/hashem/` است. ساخت carrier با `tools/build-carrier.py` و Go درج‌شده در `addon/hashem-core-build.json` و سپس `tools/package-carrier-source.py` انجام می‌شود. منابع دانلودها، نسخه‌ها و hashها در [SOURCES](SOURCES.md) و manifestهای addon هستند. این انتشار برای بررسی است؛ تا تکمیل موارد گزارش‌شده و آزمون VPS، عنوان Stable ندارد.
