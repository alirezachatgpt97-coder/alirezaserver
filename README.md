## پیش‌نیاز و نصب تک‌خطی

Ubuntu 24.04 یا Debian 12/13، systemd، amd64 یا arm64، دسترسی root، TUN فعال و اینترنت برای دریافت بسته‌های رسمی لازم است. هدف نصب پایه یک هسته و ۱ GiB RAM است؛ مصرف زیر بار به سرویس‌ها و کاربران بستگی دارد. مدل AI محلی نصب نمی‌شود. سرویس مستقل AdGuard قدیمی یا پورت‌های اشغال‌شده بدون تأیید حذف نمی‌شوند.

**ابتدا تمام فایل‌های نسخهٔ جدید را روی مخزن خودتان قرار دهید.** تا پیش از آپلود، این دستور نسخهٔ موجود در GitHub را می‌گیرد، نه فایل اصلاح‌شدهٔ محلی:

```bash
curl -fsSL https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezaserver/main/setup.sh -o alirezaserver-setup.sh && sudo bash alirezaserver-setup.sh
```

`setup.sh` فایل مستقل **install.sh** را دریافت می‌کند، SHA-256 آن را با مقدار ثبت‌شده در راه‌انداز کنترل می‌کند و سپس نصب را آغاز می‌کند. فایل `install.sh` خودش نیز تمام منابع runtime افزونه‌ها را درون خود دارد؛ نصب دستی چندمرحله‌ای لازم نیست. نصب آنلاین است و بستهٔ آفلاین باینری نیست.

اگر ZIP را دارید، در ریشهٔ آن اجرا کنید:

```bash
sudo bash install.sh
```

پرسش‌های اصلی نصب نوا حفظ شده‌اند. پیام پایان نوا به‌تنهایی پایان این ادغام نیست؛ منتظر **ALIREZASERVER READY** بمانید. نصب موجود نوا دوباره ساخته یا نصب نمی‌شود. نصب تازه از آرشیو رسمی آماده و pinned استفاده می‌کند؛ npm/build روی VPS اجرا نمی‌شود.

## ارتقای نصب موجود

از پشتیبان خود نوا و snapshot سرور نیز استفاده کنید؛ `--backup` افزونه جایگزین snapshot کل VPS یا پشتیبان مقصد DNS نیست. سپس فایل‌های جدید را دانلود/استخراج کنید و در ریشهٔ بسته اجرا کنید:

```bash
sudo bash install.sh --backup
sudo bash install.sh --repair
sudo bash install.sh --check
```

حساب‌های OpenVPN، رمزها، لینک‌های اشتراک، CA و گواهی‌ها، اطلاعات مقصدها و کلید رمزگذاری حفظ می‌شوند. فایل‌های اصلی نوا و دیتابیس کاربران/نودها/اینباندهای آن توسط توسعهٔ این افزونه جایگزین نمی‌شوند. AdGuard YAML موجود ساختهٔ دوباره نمی‌شود و مهاجرت خودکار DNS نسخه‌های قدیمی دیگر اجرا نمی‌شود. ترمیم ممکن است برای اعمال کد جدید، نوا را یک‌بار restart کند؛ ترمیم بی‌تغییر، سرویس سالم را بی‌دلیل restart نمی‌کند.

[راهنمای دقیق ارتقا و بازگشت](docs/UPGRADE.md) را پیش از ارتقای تولیدی بخوانید. شکست نصب در `failed-stage` ثبت می‌شود؛ همان فایل را دوباره اجرا کنید و از پاک‌کردن VPS خودداری کنید.

## OpenVPN

صفحهٔ مستقل با فونت وزیرمتن خود نوا، رنگ/تم هماهنگ، کارت، جدول، فرم و پنجره‌های موبایل دارد. هیچ پروتکل یا تنظیم قبلی OpenVPN حذف نشده است.

1. سرور OpenVPN بسازید: آدرس عمومی مستقیم، TCP/UDP، پورت آزاد، subnet خصوصی بدون هم‌پوشانی، DNS، MTU، رمزنگاری و گزینه‌های موجود.
2. حساب بسازید و سرورهای مجاز، تعداد دستگاه، سهمیه و انقضا را مطابق نیاز تنظیم کنید. رمز حداقل ۱۲ نویسه دارد؛ هنگام ویرایش، رمز خالی یعنی حفظ رمز قبلی.
3. از **مشخصات حساب**، نام کاربری و رمز را با کنترل نمایش/پنهان‌کردن ببینید یا کپی کنید. این مسیر فقط برای مدیر اصلی است. رمز حساب قدیمی که فقط hash دارد قابل بازیابی نیست؛ ابتدا رمز جدید تعیین کنید.
4. فعال/غیرفعال، حذف و صفرکردن مصرف با تأیید انجام می‌شوند. تغییر حساب اتصال‌های فعلی همان حساب را قطع می‌کند؛ خطای قطع اتصال پنهان نمی‌شود.
5. **لینک اشتراک مستقل** را به صاحب حساب بدهید. لینک تصادفی و قابل تعویض/لغو است؛ دارندهٔ لینک به مشخصات همان حساب و فایل سرورهای مجاز آن دسترسی دارد. لینک را محرمانه نگه دارید.
6. کاربر فایل `.ovpn` را در OpenVPN Connect یا کلاینت سازگار وارد و با نام کاربری/رمز متصل می‌شود. راهنمای کوتاه، کپی و کنترل نمایش رمز داخل صفحهٔ اشتراک موجود است.

اعداد فنی، IP، پورت، مصرف و تاریخ فنی با ارقام انگلیسی نمایش داده می‌شوند. متن صفحه فارسی/انگلیسی است. آمار از حساب‌ها، hookها و فایل وضعیت واقعی OpenVPN به دست می‌آید؛ آمار نمایشی ساختگی وجود ندارد. مسیر اینترنت IPv4، منع نشت IPv6، TLS-Crypt و تنظیمات قبلی حفظ شده‌اند. پورت انتخابی را در فایروال سرویس‌دهنده نیز باز کنید.

## نصب مقصد alirezadns

این بخش **HyperDNS را روی VPS مقصد مستقل** نصب می‌کند، نه روی سرور اصلی. نوا، AdGuard، OpenVPN و پورت‌های سرور اصلی به‌خاطر عملیات مقصد تغییر نمی‌کنند. مقصدی که نصب اصلی نوا/alirezaserver دارد رد می‌شود.

1. IP عمومی یا نام دامنهٔ SSH، پورت SSH، کاربر و دامنهٔ پنل مقصد را وارد کنید. کاربر باید root یا دارای `sudo -n` بدون رمز باشد؛ sudo تعاملی پشتیبانی نمی‌شود.
2. رمز SSH یا کلید خصوصی RSA/ECDSA/Ed25519 و عبارت عبور اختیاری را وارد کنید. این اطلاعات روی سرور اصلی ذخیره نمی‌شوند و از argv عبور نمی‌کنند.
3. **بررسی هویت SSH** را بزنید؛ IP انتخاب‌شده و اثرانگشت نمایش داده می‌شود. آن را با منبع معتبر مقصد تطبیق دهید. این مرحله هنوز احراز هویت یا نصب نیست.
4. بعد از تأیید اثرانگشت، **بررسی اتصال و پیش‌نیازها** را بزنید. ورود، دسترسی root/sudo، سیستم‌عامل، معماری، systemd، دامنه، دیسک و پورت‌های لازم بررسی می‌شوند. این مرحله بسته‌ای نصب و سرویسی متوقف نمی‌کند.
5. **نصب و اتصال خودکار** را صریحاً تأیید کنید. مراحل واقعی download، packages، configuration، service-start و health نمایش داده می‌شوند؛ درصد ساختگی ندارند. اثرانگشت/preflight پنج دقیقه اعتبار دارد؛ پس از تغییر ورودی دوباره بررسی کنید.
6. عملیات در پس‌زمینه انجام می‌شود. بستن صفحه وضعیت را از بین نمی‌برد. restart پنل، عملیات قطع‌شده را «نیازمند بررسی/ادامه» نشان می‌دهد؛ رمز/کلید برای ادامهٔ خودکار ذخیره نشده است. دوباره با بررسی هویت و پیش‌نیاز متصل شوید؛ مقصد مدیریت‌شدهٔ موجود با تنظیماتش نگه داشته می‌شود.
7. فهرست مقصدها، نسخهٔ **هنگام اتصال**، مشخصات اولیه، تنظیم اتصال و بررسی واقعی HTTPS را در همان صفحه ببینید. نسخهٔ زنده و پنل کامل HyperDNS از مسیر ورود به پنل مقصد در دسترس‌اند.

رکورد A دامنه باید مستقیم به IP مقصد باشد؛ CDN/proxy و AAAA اشتباه مانع صدور گواهی/اتصال می‌شوند. فایروال سرویس‌دهنده نیز لازم است. پورت‌های مقصد: 53 TCP/UDP، 80/443، 8080، 853، 8443 و مسیرهای بازی 5222/5223/2099/8393 TCP. توضیحات کامل قابلیت‌های HyperDNS و پورت‌ها در [راهنمای قبلی](docs/LEGACY-0.5.md#alirezadns) حفظ شده است.

آپدیت مستقل مقصد، checksum، کنترل قرارداد UI، backup و rollback قبلی حفظ شده‌اند. بررسی سلامت هنگام نصب/آپدیت شامل HTTPS و TCP/UDP DNS است. بررسی دکمهٔ صفحهٔ اصلی فقط HTTPS است و ظرفیت یا صحت همهٔ دامنه‌های DNS را تضمین نمی‌کند. رمز اولیه مقصد ممکن است پس از تغییر در HyperDNS دیگر رمز جاری نباشد.

## AI با API رسمی Gemini

مالک و ادمین/فروشندهٔ دارای نشست معتبر می‌توانند صفحهٔ **AI** را باز کنند. تنظیم/تعویض/حذف کلید و سیاست مصرف فقط برای **مدیر اصلی** مجاز است. تاریخچه بر اساس شناسه و نقش حساب جداست.

1. مدیر اصلی در تنظیمات AI کلید API خودش را وارد و ذخیره می‌کند. لازم نیست در چت توسعه کلیدی بدهید.
2. **دریافت مدل‌های سازگار** را بزنید. فهرست واقعی API و `supportedGenerationMethods` خوانده می‌شود؛ نام مدل ثابت و حدس‌زده‌شده‌ای به‌عنوان پیش‌فرض وجود ندارد.
3. مدل، حداکثر توکن پاسخ و تعداد درخواست در دقیقه برای هر حساب را تنظیم کنید. ادمین‌ها می‌توانند برای گفت‌وگو مدل سازگار انتخاب کنند، ولی کلید و سیاست سراسری را تغییر نمی‌دهند.
4. گفت‌وگو دربارهٔ پروتکل‌ها، DNS/TLS، نودها، عیب‌یابی و تنظیمات را آغاز کنید. پاسخ تدریجی، توقف، retry، کپی، نمایش قطعه‌کد، گفت‌وگوی جدید و حذف تاریخچه موجود است.

کلید در vault رمزگذاری‌شدهٔ سرور ذخیره و فقط در header درخواست HTTPS رسمی استفاده می‌شود؛ مرورگر، URL و پاسخ تنظیمات کلید را دریافت نمی‌کنند. هیچ مدل محلی، shell/tool execution یا تغییر خودکار کاربر، فایروال و تنظیمات وجود ندارد. پاسخ با متن و nodeهای امن نمایش داده می‌شود؛ HTML مدل اجرا نمی‌شود.

اطلاعات پنل خودکار ارسال نمی‌شود. دکمهٔ **پیش‌نمایش وضعیت برای ارسال** فقط برای مالک، تعداد حساب/نشست و نوع/وضعیت سرویس‌ها را بدون نام، IP، رمز و کلید نشان می‌دهد؛ پس از تأیید، به کادر پیام اضافه می‌شود و **هنوز ارسال نمی‌شود** تا خودتان ارسال را بزنید. لاگ خودکار جمع‌آوری/ارسال نمی‌شود. الگوهای شناخته‌شدهٔ رمز، API key، Bearer و private key پاک‌سازی می‌شوند، اما این تشخیص کامل همهٔ اسرار احتمالی نیست؛ متن را بررسی کنید و اطلاعات محرمانه وارد نکنید.

متن گفت‌وگو و زمینهٔ اخیر آن به Gemini ارسال می‌شود. تاریخچهٔ محلی در جدول پیام‌های `ai.db` ذخیره و صفحه‌بندی می‌شود؛ پیام‌های قدیمی‌تر با دکمهٔ مربوط قابل مشاهده‌اند. تاریخچه با حذف گفت‌وگو از فهرست فعال حذف می‌شود؛ backupهای قبلی مستقل‌اند و ممکن است نسخهٔ قبلی را نگه دارند. SQLite حذف منطقی را معادل پاک‌سازی امن رسانه نمی‌کند. حذف کلید، تاریخچه را حذف نمی‌کند.

نبود کلید، رد دسترسی، اتمام سهمیه، قطع شبکه و پاسخ نامعتبر، سایر بخش‌های پنل را غیرفعال نمی‌کنند. هزینه و سهمیهٔ واقعی تابع پروژهٔ Google کاربر است؛ محدودیت محلی جای سهمیهٔ Google نیست. مستندات و منابع رسمی در [SOURCES.md](SOURCES.md) آمده‌اند.

## به‌روزرسانی نوا، نودها و نگهداری

```bash
sudo bash install.sh --update
sudo bash install.sh --update-status
sudo bash install.sh --backup
sudo bash install.sh --check
```

timer قبلی هر شش ساعت انتشار رسمی نوا را بررسی می‌کند. فایل‌های افزونه در `/opt/alirezaserver` از `/opt/nova-node-agent` جدا هستند. updater رسمی guard شده است؛ قبل از تعویض، metadata/checksum، archive، runtime، قرارداد HTML/auth/theme و **شناسهٔ واقعی مالک در HTTP آزمایشی** بررسی می‌شوند. snapshot و journal تراکنش و rollback پس از شکست سلامت حفظ شده‌اند. نسخهٔ ناسازگار شناخته‌شده کورکورانه اعمال نمی‌شود؛ سازگاری همهٔ نسخه‌های آینده تضمین نیست.

پارامترهای `NOVA_JOIN_URL`، `NOVA_JOIN_TOKEN` و `NOVA_JOIN_PIN` و مسیر نصب child node حفظ شده‌اند؛ افزونه‌ها روی child بدون پنل مدیریت تحمیل نمی‌شوند. بازگشت `--rollback` فقط افزونه‌ها را غیرفعال می‌کند و معادل بازیابی نسخهٔ قبلی داده/کد نیست؛ [راهنمای بازگشت](docs/UPGRADE.md) را ببینید.

| مشکل | بررسی |

| نصب ناقص | `/var/log/alirezaserver/` و `/var/lib/alirezaserver/failed-stage`؛ همان فایل را دوباره اجرا کنید |

| preflight مقصد | دامنهٔ مستقیم، systemd، فضای دیسک و تداخل پورت؛ هیچ سرویس موجود خودکار حذف نمی‌شود |
| HTTPS مقصد | گواهی معتبر، دامنه/IP/panel port/admin path؛ تنظیم اتصال را هماهنگ کنید |
| Gemini بدون کلید یا مدل | مالک کلید را ذخیره کند، سپس مدل‌های واقعی را دریافت و انتخاب کند |
| Gemini quota / 403 | سهمیه و محدودیت کلید/دسترسی API و کشور/شبکهٔ سرور؛ retry نامحدود خودکار ندارد |
| مصرف RAM یا دیسک | [راهنمای منابع](docs/RESOURCES.md)، سرویس‌های واقعی و journal؛ بدون حذف امکانات ظرفیت‌بندی کنید |

نام کاربری/رمز، URL اشتراک، کلید و فایل نشست را در گزارش عمومی خطا منتشر نکنید.

## توسعه و بررسی

منابع `addon/` را ویرایش و سپس `python3 tools/build.py` اجرا کنید؛ این کار هم embedded installer و هم hash راه‌انداز را هماهنگ می‌کند. بعد از تغییر نهایی فایل‌ها، `python3 tools/package.py` را برای بازسازی `SHA256SUMS` و ZIP اجرا کنید. روی VPS تولیدی توسعه/build لازم نیست.

```bash
bash install.sh --self-test
python3 tests/regressions.py
node --test tests/backend.mjs tests/ai.mjs tests/dns.mjs tests/dns-readonly.mjs
```

آزمون‌های نوا/DOM/مرورگر اختیاری و راه اجرای آن‌ها در [VALIDATION.md](docs/VALIDATION.md) است. وابستگی توسعهٔ jsdom/Playwright در runtime سرور نصب نمی‌شود.

کد افزونه طبق اعلان قبلی GPL-3.0-or-later است. نوا مجوز مستقل خود را دارد؛ مالکیت یا مجوز آن تغییر نکرده است. مجوزهای AdGuard، HyperDNS و اقتباس‌های OpenVPN در فایل‌های اعلان داخل `addon/` حفظ شده‌اند.
