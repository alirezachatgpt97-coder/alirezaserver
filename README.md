# alirezaserver · 0.8.0-rc.17

پنل نوا با Alirezabot، فروش سرویس، AdGuard، نصب مقصد alirezadns و دستیار Gemini. پایهٔ بررسی‌شدهٔ این بسته **Nova 1.94.3** است؛ ارتقاهای بعدی از محافظ سازگاری عبور می‌کنند.

## نصب و ارتقا

بعد از انتشار فایل‌های این بسته در مخزن:

```bash
curl -fL --connect-timeout 15 --max-time 180 https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezaserver/main/install.sh -o install.sh && sudo bash install.sh
```

برای نصب موجود، ابتدا از `sudo alireza` پشتیبان بگیرید و بیرون سرور نگه دارید. اجرای دوبارهٔ نصاب برای ارتقا/تعمیر است؛ VPS یا دیتابیس را پاک نکنید. نصاب آنلاین است و وابستگی‌های رسمی را دانلود می‌کند؛ روی VPS رابط کاربری build نمی‌شود.

## تغییرات این نسخه

- پایهٔ نوا 1.94.3 و بررسی سازگاری API، سهمیهٔ نمایندگان و تولید لینک.
- انتخاب «همین سرور / سرور دیگر» در نصب ربات مالک؛ SSH با تأیید اثرانگشت، رمز یا کلید و root یا sudo بدون رمز.
- در نصب مقصد، PHP، دیتابیس و پردازش ربات روی مقصد هستند؛ وب ربات از همان HTTPS پنل نمایش داده می‌شود. ارتباط رفت‌وبرگشت در SSH و روی loopback است؛ پورت عمومی تازه‌ای باز نمی‌شود. روی سرور اصلی PHP/MariaDB برای این حالت نصب نمی‌شود.
- در محصولات پنل وب میرزا، انتخاب سرویس: اینباندهای فعال نوا، AmneziaWG، MTProto، mieru، SOAR، Telegram Web، Smart DNS و VIP، OpenVPN و alirezadns مقصد.
- فقط سرویس‌های آماده و مجاز قابل فروش‌اند؛ گزینهٔ استاندارد رفتار محصولات قدیمی را حفظ می‌کند. فروش alirezadns مقصد و OpenVPN فعلاً مختص ربات مالک است؛ نماینده سرویس‌های نوا را در محدودهٔ مجوز واقعی خودش می‌فروشد.
- نشان سرویس در دکمهٔ محصول و راهنمای تحویل در تلگرام؛ کنترل سازگاری تمدید پیش از کسر موجودی در مسیر اصلی ربات.

## راه‌اندازی ربات روی سرور دیگر

در Alirezabot، «سرور دیگر» را انتخاب کنید، مشخصات SSH و توکن ربات را وارد کنید و اثرانگشت را با کنسول مقصد تطبیق دهید. مقصد پیشنهادی Ubuntu 24.04 یا Debian 12/13 با systemd، IPv4 عمومی و دسترسی خروجی به مخازن و Telegram داشته باشد. وب مستقل ربات همچنان از لینک پنل اصلی باز می‌شود. با بستن صفحه، کار ثبت‌شده در پنل ادامه دارد؛ پس از restart پنل وضعیت را بررسی کنید و در صورت نیاز نصب را برای تعمیر تکرار کنید.

نصب مقصد با انتقال دیتابیس یک ربات نصب‌شده روی سرور اصلی یکی نیست؛ تغییر محل یک نصب موجود برای جلوگیری از دو polling و گم‌شدن سفارش‌ها به مهاجرت جداگانه نیاز دارد. نصاب آن را کورکورانه انجام نمی‌دهد. برای ارتقای فایل‌های ربات مقصد، همان مقصد و اطلاعات SSH را در فرم نصب دوباره وارد کنید. داده و رمز قبلی حفظ می‌شوند، مگر خودتان بازنشانی رمز را انتخاب کنید.

## فروش سرویس‌ها

1. سرویس را اول در پنل اصلی فعال و سالم کنید.
2. در پنل وب میرزا → محصولات، پنل مدیریت‌شدهٔ `alirezaserver` را انتخاب کنید.
3. در «سرویس‌های قابل فروش این محصول» نوع و دسترسی‌ها را انتخاب کنید؛ قیمت، حجم و مدت همان فرم قبلی‌اند.
4. برای alirezadns، ابتدا مقصد را در نصب‌کنندهٔ alirezadns ثبت کنید؛ سپس در Alirezabot پنل اصلی، کلید API همان مقصد را بررسی و ذخیره کنید. API باید از سرور اصلی قابل دسترسی باشد. تنظیم Public API را در خود مقصد با آگاهی مدیریت کنید؛ این افزونه آن را پنهانی باز نمی‌کند. AdGuard محصول alirezadns نیست و تغییر نمی‌کند.
5. یک خرید کنترل‌شده، تمدید، تعلیق و لینک مشتری را آزمایش کنید. صفحهٔ اختصاصی OpenVPN مشخصات ورود و دانلود کانفیگ را می‌دهد؛ صفحهٔ DNS مسیر ثبت IP را ارائه می‌کند. Smart DNS تضمین NAT یا دسترسی به همهٔ بازی‌ها نیست.

تعویض نوع سرویس یا مقصد یک حساب در تمدید، مهاجرت نیست و رد می‌شود. برای DNS مقصد، تمدید زمانی مطابق API آن به روزهای کامل افزایشی محدود است؛ کوتاه‌کردن انقضا یا تبدیل محدود به نامحدود را در خود مقصد مدیریت کنید. در پاسخ نامطمئن ساخت DNS، حساب با نام مخصوص سفارش جست‌وجو می‌شود؛ اگر نتیجه روشن نباشد، درخواست ساخت دوم کورکورانه ارسال نمی‌شود.

## مدیریت و پشتیبان

```bash
sudo alireza
sudo bash install.sh --check
sudo bash install.sh --update-status
sudo bash install.sh --update
sudo bash install.sh --diagnose
```

پشتیبان افزونه، در حالت ربات مقصد، snapshot دیتابیس و فایل‌های ربات را از مسیر خصوصی دریافت و در `remote-bot/alirezabot.tar.gz` داخل آرشیو قرار می‌دهد؛ مقصد قطع باشد، backup کامل پذیرفته نمی‌شود. کلید SSH، گواهی‌ها و backup محرمانه‌اند. بازیابی ربات مقصد باید روی همان مقصد با بازگرداندن dump و فایل‌های خودش انجام شود؛ بازیابی فایل‌های اصلی پنل به‌تنهایی دیتابیس مقصد را restore نمی‌کند.

پورت‌های متداول: عمومی TCP 443؛ TCP 80 در صورت نیاز HTTP-01؛ داخلی `127.0.0.1:8088` و `127.0.0.1:10085`؛ DNS طبق تنظیم TCP/UDP 53؛ پورت‌های پروتکل طبق انتخاب پنل. در حالت ربات مقصد دو پورت loopback آزاد برای SSH انتخاب می‌شوند و سرویس‌های موجود تغییر نمی‌کنند.
