# alirezaserver · 0.8.0-rc.14

پنل نوا با مدیریت یکپارچهٔ پروتکل‌ها، AdGuard، نصب مقصد alirezadns، دستیار Gemini و Alirezabot. این نسخه نامزد انتشار است؛ نتیجهٔ آزمون‌ها و موارد آزمایش‌نشده در [گزارش اعتبارسنجی](docs/RC14-VALIDATION.md) آمده‌اند.

## انتشار در GitHub — فقط یک بار

فایل ZIP بیرونی را Extract کنید و **همهٔ محتویات آن** را در ریشهٔ مخزن `alirezachatgpt97-coder/alirezaserver` جایگزین کنید:

- `install.sh`، `setup.sh`، `README.md`، `CHANGELOG.md`، `SOURCES.md`، `LICENSE`، `SHA256SUMS`
- پوشهٔ `docs` و **خود فایل `source-code.zip` بدون Extract**.

تعداد فایل‌های بستهٔ بیرونی کمتر از ۱۰۰ و اندازهٔ هر فایل کمتر از ۲۵ MiB است. سورس ماژولار، آزمون‌ها و گزارش‌های قدیمی همگی در `source-code.zip` قرار دارند. فایل‌های موجود دیگر مخزن را کورکورانه حذف نکنید. این بسته در GitHub منتشر نشده است؛ تا زمان انتشار، دستور زیر فایل قبلی مخزن را دریافت می‌کند.

## نصب تازه یا ارتقای نسخهٔ موجود

ابتدا از پنل موجود با `sudo alireza` پشتیبان بگیرید و نسخه را خارج از VPS نگهداری کنید. سپس پس از انتشار بسته در مخزن:

```bash
curl -fL --connect-timeout 15 --max-time 180 https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezaserver/main/install.sh -o install.sh && sudo bash install.sh
```

نصاب آنلاین است و وابستگی‌های رسمی را دانلود می‌کند؛ خودش سورس و فایل‌های افزونه را درون فایل دارد. روی سرور، پروژهٔ رابط کاربری را build نمی‌کند. پایهٔ نصب تازه نوا **1.92.3** است و در پایان نصب، آخرین نسخهٔ رسمی را با محافظ سازگاری بررسی می‌کند. اگر نسخهٔ جدید ناسازگار یا دریافت آن ناموفق باشد، پایهٔ تأییدشده حفظ و علت ثبت می‌شود؛ نسخهٔ ناسازگار بی‌بررسی نصب نمی‌شود.

اجرای دوباره برای ارتقا/تعمیر پشتیبانی می‌شود. دیتابیس، پلن‌ها، کلیدهای Gemini و ربات، گواهی‌ها، AdGuard و حساب‌های موجود نباید با مقادیر پیش‌فرض جایگزین شوند. ابتدا همین نصاب جدید را اجرا کنید؛ دستور آپدیتِ نصاب قدیمی کد افزونهٔ جدید را نصب نمی‌کند.

```bash
sudo alireza
sudo bash install.sh --check
sudo bash install.sh --update
sudo bash install.sh --update-status
sudo bash install.sh --rollback
```

`--rollback` بازگشت افزونه‌هاست. بازگشت نوا و بازیابی نسخهٔ پشتیبان را از منوی انگلیسی `alireza` مدیریت کنید. هنگام خطا VPS را پاک یا دوباره نصب نکنید؛ لاگ مرحلهٔ شکست در `/var/log/alirezaserver/` ذخیره می‌شود.

## چه تغییر کرده است؟

- نصب پایه به نوا 1.92.3 منتقل شده؛ دکمهٔ آپدیت و تایمر شش‌ساعته از مسیر محافظت‌شده استفاده می‌کنند. نسخهٔ جدید در دیتابیس/تنظیمات موقت، پیش از جایگزینی آزمایش می‌شود. آزمون نقش و سهمیهٔ نماینده نیز به محافظ اضافه شده است.
- بخش «شبکه» از منو، نتایج جست‌وجو و ورود از hash حذف شده است. تنظیمات شبکهٔ فعال، TLS، خروجی‌های کشور و تولید کانفیگ تغییر نکرده‌اند. تنظیم ضروری TLS همچنان در `alireza` در دسترس است.
- AI و نصب مقصد alirezadns کارت‌ها، فرم‌ها و چیدمان هماهنگ با تم پنل دارند؛ کنترل‌ها و عملکرد قبلی حفظ شده‌اند. Gemini به کلید کاربر در تنظیمات نیاز دارد.
- بخش Alirezabot در پنل اصلی آیکون مستقل و چیدمان مرتب‌تر دارد؛ نوار نصب و اطلاعات ورود یک‌بارمصرف حفظ شده‌اند.
- فروش پنل نمایندگی و فروشگاه مستقل نمایندگان با کیف پول، سفارش پایدار، تحویل اطلاعات ورود و کنترل دسترسی اضافه شده است.

## فروش پنل نمایندگی از ربات اصلی

۱. ربات را از بخش Alirezabot راه‌اندازی کنید؛ PHP/MariaDB تنها با انتخاب نصب ربات اضافه می‌شوند. نصب مجدد اطلاعات حساب‌ها را حذف نمی‌کند. ارتقای این نصاب فایل‌های مدیریت‌شدهٔ ربات را با پشتیبان قبلی به‌روزرسانی می‌کند.

۲. در پنل وب مستقل ربات، با حساب مالک وارد **فروش پنل نمایندگی** شوید. یا از پنل اصلی **مرکز فروش نمایندگی** را باز کنید. پلن «Admin / Reseller panel» بسازید: قیمت ثابت یا قیمت هر GB، حداقل/حداکثر حجم، اینباندهای مجاز، تعداد کاربران، مدت مشتریان و دسترسی‌ها.

۳. مشتری در ربات اصلی «خرید پنل نمایندگی» یا `/panels` را انتخاب می‌کند. حجم سفارشی را وارد و قیمت محاسبه‌شدهٔ سرور را تأیید می‌کند. خرید از **همان موجودی واقعی کیف پول ربات اصلی** برداشت می‌شود. در پایان لینک پنل، نام حساب و رمز اختصاصی تحویل داده می‌شود؛ فرم ورود نوا بسته به نسخه ممکن است تنها رمز را بخواهد.

**تفاوت نقش‌ها:** فقط `reseller` در نوا سهمیهٔ حجمی اعمال‌شده دارد. `manager` و `admin1` دسترسی مدیریتی بدون این سهمیه دارند؛ برای فروش حجم از `reseller` استفاده کنید. مدت پلن، مدت پیش‌فرض مشتریان نماینده است، نه انقضای ساختگی برای خود حساب مدیریتی. فروش خودکار `admin1` اختیار گسترده می‌دهد و تأیید رمز مالک می‌خواهد. این تأیید به‌صورت رمز‌شده ذخیره می‌شود؛ با تغییر رمز مالک باید مجدداً تأیید شود.

سفارش پرداخت‌شده با قطع پاسخ شبکه دوباره از کیف پول برداشت نمی‌کند. نتیجهٔ نامطمئن برای بازیابی حفظ می‌شود. بازپرداخت تنها بعد از بررسی نبود حساب و دورهٔ امن انتظار امکان‌پذیر است؛ سفارش آماده را حذف و پول آن را خودکار پس نمی‌دهد. برای خرید ربات اصلی، بازپرداخت را در **صفحهٔ فروش نمایندگی همان پنل ربات** انجام دهید تا کیف پول اصلی درست اصلاح شود. بازیابی سفارش و تحویل عقب‌افتاده از زمان‌بند موجود ربات استفاده می‌کند.

## فروشگاه مستقل هر نماینده

نماینده‌ای که دسترسی `users.create` دارد، از منوی **مرکز فروش من** وارد فروشگاه خودش می‌شود. پلن مشتری، اینباند و خروجی کشور در محدودهٔ دسترسی و سهمیهٔ واقعی همان حساب است؛ حساب نماینده نمی‌تواند پلن مدیریتی بسازد یا سفارش/کیف پول دیگران را ببیند.

برای ربات فروش اختصاصی، یک توکن مستقل BotFather در تب ربات وارد کنید. توکن ربات اصلی یا توکن فروشگاه دیگر پذیرفته نمی‌شود. هر نماینده پنل فروش خود را دارد؛ polling در همان پردازش پنل انجام می‌شود و برای هر نماینده سرویس/PHP جدا نصب نمی‌شود.

کیف پول این فروشگاه‌های مستقل **از کیف پول ربات اصلی جداست**. مسیر پرداخت آن‌ها ثبت رسید `/topup مبلغ کدپیگیری` و تأیید آگاهانهٔ فروشنده است؛ این مسیر درگاه خودکار ساختگی ندارد. فروشنده دستور پرداخت و شناسهٔ مدیر را تنظیم می‌کند. مشتری با `/plans`، `/wallet`، `/orders` و `/order شناسه` خرید و تحویل را پیگیری می‌کند. وضعیت صف و خطای ارتباط در تب ربات نمایش داده می‌شود. توکن‌ها و اطلاعات تحویل در دیتابیس رمز‌شده نگهداری می‌شوند؛ پشتیبان‌ها محرمانه‌اند.

## پورت‌ها و سازگاری

| سرویس | پورت/دسترسی |
|---|---|
| ورودی عمومی پنل و پراکسی | TCP 443؛ تنظیم پورت اضافی طبق انتخاب نصب |
| HTTP و اعتبارسنجی گواهی | TCP 80؛ HTTP-01 باید از اینترنت به سرور برسد |
| API پنل | `127.0.0.1:8088`، عمومی نکنید |
| Xray API | `127.0.0.1:10085`، عمومی نکنید |
| AdGuard DNS | TCP/UDP 53 طبق تنظیم موجود؛ رابط خودش تغییر نکرده است |
| ربات PHP | سوکت محلی مدیریت‌شده، پشت پنل؛ پورت عمومی جدا ندارد |
| فروشگاه نمایندگان | همان HTTPS پنل؛ پورت جدید ندارد |
| OpenVPN و دیگر پروتکل‌ها | پورت انتخاب‌شده در پنل؛ تداخل باید بررسی شود |
| alirezadns مقصد | SSH انتخابی سرور مقصد؛ نصب تنها با اقدام صریح شما |

فایروال ارائه‌دهندهٔ VPS جدا از فایروال داخل سیستم است. دامنهٔ پروکسی‌شدهٔ Cloudflare برای همهٔ پروتکل‌ها مناسب نیست. این نسخه مسیرهای سالم تولید لینک، SNI/Host/port و گواهی را تغییر نداده است. موفقیت اتصال از شبکهٔ آزمایش، تضمین دسترسی از همهٔ اپراتورها نیست.

## به‌روزرسانی و امنیت وابستگی‌ها

Node نصب‌شده و شاخهٔ PHP مورد استفاده از مخزن APT پیکربندی‌شده به‌روزرسانی و نسخهٔ **باینری واقعی** بررسی می‌شوند. اگر مخزن نسخهٔ امن ندهد، نصاب علت را نمایش می‌دهد؛ مخزن ناشناس یا کامپایل سنگین به‌جای آن انجام نمی‌دهد. بستهٔ وصلهٔ معتبر توزیع با بررسی مالکیت باینری و changelog پذیرفته می‌شود. به‌روزرسانی امنیتی ممکن است نیازمند restart پنل یا PHP باشد.

Nginx برای معماری این بسته لازم نیست و نصب نمی‌شود؛ سرویس Nginx موجود شما نیز کورکورانه تغییر نمی‌کند. نبود PHP قبل از نصب اختیاری ربات طبیعی است. هیچ نسخه‌ای صرفاً با شمارهٔ نسخه «صددرصد امن» محسوب نمی‌شود.

## پشتیبان، عیب‌یابی و محدودیت آزمون

پشتیبان افزونه شامل snapshot سازگار SQLite برای تنظیمات/AI/فروشگاه و dump دیتابیس مدیریت‌شدهٔ ربات است. کلید رمزگشایی و گواهی‌ها باید همراه آن محفوظ بمانند؛ فایل پشتیبان را عمومی نکنید. آپدیت نوا مسیر دادهٔ افزونه را جایگزین نمی‌کند. محافظ نسخه‌های آینده را آزمایش می‌کند، ولی سازگاری نامحدود با تمام نسخه‌های آینده تضمین نیست.

```bash
sudo bash install.sh --diagnose
sudo journalctl -u nova-agent.service -n 80 --no-pager
sudo journalctl -u alireza-update.service -n 80 --no-pager
node -v
php -v
```

این نسخه در محیط محلی با API واقعی نوا، SQLite، PHP، MariaDB و چهار handshake واقعی Xray آزمایش شده است. آزمون DOM فارسی/انگلیسی انجام شده؛ مرورگر تصویری این محیط در دسترس نبود. نصب کامل روی VPS، Telegram واقعی، گرفتن گواهی از CA و تست بلندمدت کل مجموعه روی ۱ GB انجام نشده‌اند. مقدار مصرف کنترلر در گزارش آمده است و معادل مصرف کل سرویس‌ها زیر بار نیست.
